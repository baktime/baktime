A BACKUP ROUTINE, READY TO USE

Protect the data
you depend on.

Bring your own repository and schedule. baktime handles the repeatable work: connecting, backing up, keeping history, and making restores easier.

01 / DATABASES▤

MySQL & PostgreSQL

Stream database dumps straight into restic. Connect directly or securely through an SSH jump host.

02 / FILES⌘

Files over SSH

Back up remote Linux hosts, including consistent copies of live SQLite databases, without root access.

03 / HISTORY◷

Schedules & retention

Set a cron schedule per target. Keep the daily, weekly and monthly snapshots that make sense to you.

04 / RESTORES↶

Know what happened

Track health and run history, get Discord notifications, and restore a snapshot through a manual workflow.

A FEW PIECES, WORKING TOGETHER

From a schedule
to a safe copy.

Targets and credentials stay in GitHub secrets. Only names and schedules are shared with the dispatcher.

01

Describe a target

Store each database or files target as a GitHub secret. Keep credentials out of the repository.

02

Set its schedule

The lightweight Cloudflare Worker checks schedules and dispatches a job when a backup is due.

03

Save an encrypted copy

GitHub Actions runs restic. Backups are encrypted on the client and sent to R2 or another supported store.

04

Keep & restore

Retention prunes old snapshots. Run records show what happened, and a manual workflow restores a copy.

File data travels directly from the host to storage. Database dumps stream from the dump tool into restic; they are not committed to Git.

Follow the setup guide ↗
  1. 01
    Create a private repository

  2. 02
    Connect storage and secrets

    Add your restic repository, encryption password, provider credentials and target configuration as GitHub secrets.

  3. 03
    Choose schedules and retention

    Set each target’s backup frequency and how many daily, weekly and monthly snapshots to keep.

  4. 04
    Run once, then verify

    Check the first run, review the recorded status, and practice restoring before you need it.

Backups should be routine, understandable, and yours to restore.

I built baktime to make a reliable backup setup easier to operate without keeping a dedicated backup server alive. The project is open source; you choose the targets, schedules, storage provider, and retention policy.
